# ChildrenOfBottom

안드로이드 브라우저 중심, 최대 4인 실시간 멀티플레이 생존게임의 **로비 및 게임 화면 프로토타입**입니다. 기존 TRPG 규칙은 포함하지 않습니다. 시작 시 모든 클라이언트가 자신의 캐릭터 중심 게임 화면으로 전환됩니다. 공유 테스트 필드에서 이동할 수 있습니다. 생존 규칙, 전투, 저장 기능 및 Unity 연결은 아직 구현하지 않았습니다.

## 실행

Node.js 22 이상과 npm이 필요합니다.

```sh
npm ci
npm start
```

PC: http://localhost:3000 에 접속합니다. 같은 Wi-Fi의 안드로이드에서는 `http://PC의사설IP:3000`으로 접속합니다. OS 방화벽에서 3000 포트를 허용해야 할 수 있습니다. 인터넷에서 다른 네트워크의 친구와 접속하려면 WebSocket 업그레이드를 지원하는 호스트에 이 서버를 배포하고 HTTPS/WSS를 적용하세요. 현재 프로젝트는 외부 배포되지 않았습니다.

`PORT`(기본 3000), `HOST`(기본 0.0.0.0), `ALLOWED_ORIGIN`(브라우저 허용 Origin, 예: https://game.example.com)을 환경변수로 설정할 수 있습니다. 기본값은 요청 Host와 같은 HTTP/HTTPS Origin만 허용합니다. Origin 없는 네이티브 클라이언트는 허용합니다.

```sh
npm test
npm run dev
```

## 규칙과 장애 처리

- 방 코드 6자리, 최대 4명(방장 포함). 참가자 이름은 공백 제거 후 1~20자입니다.
- 방장 외 참가자 모두 준비하면 시작 가능합니다. **혼자 시작도 허용**하여 개발과 개인 확인이 가능합니다.
- 방장은 준비 버튼 대신 시작 버튼을 사용합니다. 일반 참가자는 준비/준비해제를 전환합니다.
- 게임 시작 후 신규 참가와 준비 변경은 금지됩니다. 나가기는 가능합니다.
- 대기실에서는 기존대로 방장 퇴장/연결 종료 시 방을 해제합니다. **게임 중에는 방장도 본인만 퇴장**하며 입장순으로 남은 플레이어에게 방장 권한을 넘깁니다. 남은 인원이 0명이 될 때만 게임 방을 삭제합니다. 게임 종료 규칙은 아직 없으며, 종료 처리는 추후 추가합니다.
- 서버가 15초 간격으로 ping을 전송합니다. 다음 검사까지 pong이 없으면 연결을 종료합니다(무응답 감지 약 15~30초). 명시적 연결 종료는 즉시 처리합니다. 모바일 백그라운드 전환으로 연결이 끊어져도 같은 규칙입니다.
- 브라우저는 연결 종료 시 메인으로 돌아가고 2초 간격으로 재접속합니다. 자동 방 복귀와 세션 복원은 없습니다. 대기실은 코드로 재참가할 수 있습니다. 진행 중인 방은 신규 참가와 재참가가 불가능하며, 이탈한 방장이 다시 접속해도 남은 게임에는 영향을 주지 않습니다.
- 요청 응답이 8초 동안 없으면 연결을 다시 수립합니다. 요청 중에는 중복 동작을 막습니다.
- 클립보드 복사는 HTTPS 또는 localhost에서 동작합니다. 일반 HTTP LAN 접속 등 권한이 없는 환경에서는 코드를 선택하고 수동 복사할 수 있도록 안내합니다.
- 방과 참가자는 메모리에만 존재하여 서버 재시작 시 사라집니다. 단일 서버 프로세스용입니다.

## 구조

- `server.js`: HTTP 정적 파일 제공, WebSocket 서버, 방 상태/권한/입력 검증
- `public/`: 한국어 반응형 UI. 로비 좌측 2/3 참가자 목록과 우측 조작부
- `test/lobby.test.js`: 실제 네트워크 연결을 통한 통합 테스트
- [PROTOCOL.md](PROTOCOL.md): 향후 Unity용 JSON WebSocket 계약

서버는 신뢰할 수 없는 클라이언트가 보낸 방장 ID/참가자 ID/방 상태를 사용하지 않습니다. 연결마다 발급한 ID와 서버 소유 방 상태로 권한을 확인합니다. 메시지 크기 4 KiB, 연결당 10초에 160요청 (이동 입력 포함), 방 1,000개 제한과 느린 수신자 종료가 적용됩니다. 계정 인증 및 IP별 접속 제한은 아직 없습니다. 방 코드는 초대용이며 영구 인증 수단이 아닙니다. 공개 운영 전에는 서비스 규모에 맞는 접속 제한과 운영 모니터링이 필요합니다.

## 확인 방법

브라우저 탭 4개에서 서로 다른 이름으로 접속하여 방을 생성하고 같은 코드로 참가합니다. 준비 전에는 시작이 비활성화되고 모든 참가자가 준비하면 활성화되는지 확인합니다. 다섯 번째 참가를 거절하는지, 일반 참가자 퇴장과 방장 퇴장/탭 종료 결과가 다른지 확인합니다. 안드로이드에서는 세로 화면, 코드 복사와 네트워크 끊김도 확인합니다.

자동 테스트는 4인 상태 동기화, 정원 초과, 권한 위조, 준비 토글과 타입 검사, 시작 후 참가 거절, 퇴장/연결 종료/heartbeat, 혼자 시작, 잘못된 JSON/버전/코드, 정적 파일 제한을 검증합니다.

사용한 WebSocket 구현과 heartbeat 처리 참고: [ws 공식 문서](https://github.com/websockets/ws/blob/master/README.md).

## 게임 화면 및 조작

- 각 플레이어는 화면 중앙의 자기 캐릭터를 기준으로 같은 필드를 봅니다. 서버가 이동 속도(220/초), 대각선 정규화, 필드 경계(각 축 ±1500)를 검증합니다. 20Hz 스냅샷을 공유하고 350ms 이상 입력이 없으면 이동/행동을 멈춥니다.
- 터치 기기는 좌하단 이동 조이스틱과 우하단 A·B 버튼을 사용합니다. 이동과 행동을 동시에 터치할 수 있습니다.
- 키보드는 WASD/방향키로 이동, J=A / K=B입니다. A·B는 현재 입력과 캐릭터 테두리 표시만 구현했으며 공격·상호작용 기능은 아직 지정하지 않았습니다.
- 정밀 포인터가 감지되거나 실제 키보드/마우스 입력이 들어오면 터치 조작부를 숨깁니다. 브라우저에는 연결된 모든 키보드를 입력 전에 확인하는 표준 API가 없어, 키보드만 연결된 경우 첫 키 입력 시 숨겨집니다. 정밀 포인터 연결 해제가 감지되면 터치 조작부가 다시 표시됩니다.
- 좌상단 ☰ / Escape로 중앙 메뉴를 열고 계속하기 또는 나가기를 선택합니다. 메뉴는 본인 입력만 멈추며 다른 플레이어를 일시정지하지 않습니다. 나가기는 본인만 방에서 제거하고 메인으로 복귀합니다.
- 서버 프로세스 종료/재시작 후 방 복원은 지원하지 않습니다. 이 구현은 게임 클라이언트인 방장의 연결 종료에도 방을 유지하는 기능입니다.

추가 검증: 게임 중 방장 퇴장/heartbeat 만료 후 잔여 플레이어 유지, 최종 인원 퇴장 후 삭제, 이동 입력 검증·대각선 속도·타인 제어 방지·무입력 정지·경계 제한.

## 공통 스테이터스와 오브젝트 HUD

플레이어·NPC·적의 공통 스테이터스 및 플레이어 전용 스킬덱/스킬목록을 구현했습니다. 기본값과 추가 수치, 회복/사망/기절/이동 적용 규칙, 최근접 대상 및 생성 API는 [STATUSES.md](STATUSES.md)를 참고하세요.

모든 개체 위에는 체력바와 왼쪽 레벨을 표시합니다. 내 체력바는 청록색, 다른 플레이어·적은 붉은색, NPC는 녹색입니다. 개체 아래의 현재/최대 스킬자원은 최종 최대치가 0일 때 숨깁니다. NPC/적 자동 배치와 AI·전투 규칙은 아직 없습니다.

테스트: 공통 기본값/개체ID/플레이어 전용 필드, 추가 수치/회복 상한/사망, 최근접 참조 갱신, HUD 색·비율·레벨·자원 표시, NPC·적 스냅샷, 서버 스테이터스를 사용한 기절·사망·이동속도 처리를 검증합니다. 클라이언트 테스트는 브라우저 API 대역을 사용하며 실제 기기 화면 검증은 별도로 필요합니다.

## 가로 전용 카메라와 화면 배율

게임 화면은 가로 전용이며 세로로 잡으면 회전 안내를 표시하고 본인 조작을 멈춥니다. 회전해도 다른 플레이어의 게임 진행은 유지됩니다. 로비/메인에서는 세로로 방을 준비할 수 있고 실제 플레이에서만 가로 화면을 요구합니다.

- 기본 시야는 가로:세로 **19:10**입니다.
- 현재 플레이어 표시 지름 36 좌표를 1 시야 단위로 삼아 가로 시야를 **19(684 좌표)**로 고정합니다. 해상도가 높아져도 가로로 더 멀리 보이지 않고 화면 배율이 달라집니다. 실제 충돌 히트박스를 새로 추가하는 변경은 아닙니다.
- 세로 시야는 `clamp(19 × 화면높이 / 화면너비, 8, 15)`로 조정합니다. 19:8~19:15 사이에서는 화면을 채우고, 더 넓으면 좌우 여백, 더 높으면 위아래 여백을 둡니다. 월드와 캐릭터를 가로/세로로 찌그러뜨리지 않습니다.
- 플레이어는 유효 게임 화면 중앙에 있고, 메뉴/조이스틱/A·B는 여백을 제외한 게임 화면 모서리에 배치합니다. 터치 UI는 CSS 픽셀 크기를 유지해 조작성을 확보합니다.
- 화면 회전, 창 크기 변경, 접힘/펼침으로 viewport 크기가 바뀌면 즉시 다시 계산합니다. 브라우저의 강제 화면 회전/전체화면 권한을 요구하지 않으며 사용자가 기기를 가로로 돌려 사용합니다.

## 웹 게스트와 APK 계정 (최신 접속 정책)

웹은 항상 게스트입니다. 세로 웹 화면은 19:10으로 고정·축소하여 계속 플레이할 수 있습니다. 이 동작이 위의 이전 '세로에서 회전 안내' 설명보다 우선합니다. APK는 별도 로그인 UI와 서버 계정/설정 API를 사용하고 가로 사용을 유지합니다.

구글·카카오 OAuth 서버 코드, 계정별 설정 저장 및 Android WebView 프로젝트를 추가했습니다. 실제 인증키 설정, HTTPS 계정 서버 배포, APK 빌드·실기기 검증은 남아 있습니다. 세부 설정/범위와 테스트 링크 기록은 [WEB-AND-APK.md](WEB-AND-APK.md)를 참고하세요.

플레이어 표시는 이동 방향으로 꼭짓점이 향하는 삼각형입니다. 정지하면 마지막 방향을 유지하며, 서버가 방향을 동기화해 다른 접속자도 같은 방향을 봅니다. NPC/적은 원형을 유지합니다. 방향은 실제 이동에 따라 갱신하고 기존 원의 반지름 18에 삼각형을 내접시켜 전체 크기·카메라 배율 기준을 유지합니다.
