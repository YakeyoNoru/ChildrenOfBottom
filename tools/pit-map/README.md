# 구덩이 구현로직 v4 — 추가 타일 확률 적용

기본 1~50번은 항상 포함합니다. 추가 번호는 각각 독립 추첨하고, 뽑힌 번호를 확정한 다음 지도 전체를 구성합니다.

| 번호 | 높이 | 종류 | 각 타일의 생성 확률 |
|---|---:|---|---:|
| 51~55 | 1 | 일반필드 | 80% |
| 56~58 | 2 | 풍요필드 | 50% |
| 59 | 3 | 일반필드 | 30% |
| 60 | 3 | 풍요필드 | 30% |

59번과 60번은 별개입니다. 추가 타일이 빠져도 번호를 당기지 않습니다. 타일 수는 50~60개이며 평균 기대값은 56.1개입니다.

## 실행

`../../public/pit-map.html`을 Chrome/Edge로 열면 됩니다. 서버, 외부 네트워크, 별도 설치가 필요하지 않습니다. 새 랜덤 게임을 누를 때마다 추가 타일을 먼저 추첨하며, 선택 번호와 묶음 크기를 화면에 표시합니다. 같은 시드는 Python과 브라우저에서 같은 타일·좌표·다리를 재현합니다.

WASD·방향키·화면 버튼으로 이동하고 M으로 전체 지도를 봅니다. 맵 JSON 저장으로 이번 게임에서 확정된 전체 데이터를 내려받을 수 있습니다. 시드 29는 60개 전부 생성, 56791은 추가 타일 없이 50개, 20261030은 55개 샘플입니다.

Python에서는 외부 의존성 없이 다음 명령으로 생성·검증할 수 있습니다.

```
python generate.py --seed 20261030 --out map.json
python verify.py map.json
python test.py
```

## 생성과 확률 보존

추가 타일은 열 번의 서로 다른 난수 추첨으로 결정됩니다. 추첨 난수와 배치 변형 난수를 분리하므로 배치 시도 횟수가 타일 생성 확률에 영향을 주지 않습니다.

높이 1의 추가 개수는 0~5개, 높이 2는 0~3개, 높이 3은 0~2개여서 수량 조합은 총 72개입니다. 각 수량 조합의 구조를 제약 풀이로 미리 확보하고 독립 검증했습니다. 게임 시작 때는 정확히 해당 수량의 구조를 사용하고, 추첨된 번호·지형 종류를 배정한 뒤 회전·반사를 적용합니다. 구조 선택 실패를 이유로 타일을 빼거나 다시 추첨하지 않습니다.

현재 구조 자료는 수량 조합당 한 개로 총 72개입니다. 같은 수량에서는 기본 구조를 공유하며 번호·일반/풍요 배정과 회전·반사를 통해 달라집니다. 자유로운 윤곽과 다리 구조를 매번 새로 푸는 방식보다 구조적 다양성이 제한됩니다. 구조를 더 확보하거나 실시간 풀이로 확장할 수 있습니다.

`python generate.py --seed 20261030 --out map.json --live`는 선택 번호를 유지한 채 실시간으로 새 구조를 풉니다. 이 경우 OR-Tools가 필요합니다. 제한 시간에 해를 찾지 못하면 실패로 보고하며 추가 타일은 다시 추첨하지 않습니다. `build_bank.py`는 모든 수량 조합의 구조 자료를 구축하는 도구입니다.

## 물리적 연결과 통행 방향

다리가 있다는 조건은 두 지형의 물리적 연결을 뜻하며 양방향 이동을 뜻하지 않습니다. 전체 지도 연결과 묶음별 위·아래 연결은 물리적 다리로 검사합니다. 모든 타일 간 왕복은 요구하지 않습니다.

오직 높이 3→2 통행을 금지합니다. 2→3은 가능하며 나머지 다리는 양방향입니다. 같은 다리마다 실제 통행 가능한 방향을 movementArcs에 따로 기록합니다. 높이 3 묶음의 아래쪽 다리는 높이 2에서 올라오는 진입로여도 아래쪽 연결 조건을 충족합니다. 경사·높이 자체에 별도 이동 효과는 없습니다.

구조도·미니맵·필드의 주황 화살표는 허용 방향 2→3입니다. 필드에서는 해당 다리 중앙 경계의 역방향 통과를 차단하고 다른 다리는 양방향 통행을 유지합니다. 단방향 다리 위에서의 작은 후퇴는 허용하되 중앙 경계를 넘어 높이 2로 귀환할 수는 없습니다.

높이 1의 모든 같은 높이 연결 묶음에는 시작점이 최소 한 개 있어야 합니다. 다섯 시작점을 고정 위치에 둔 뒤 남는 묶음을 만드는 대신, 묶음별 시작점 배정을 생성 제약으로 보장합니다.

## 묶음별 필수 출입 다리

| 묶음 높이 | 한 높이 위로 가는 다리 | 한 높이 아래로 가는 다리 |
|---|---|---|
| 1 | 높이 2로 최소 1개 | 해당 없음 |
| 2 | 높이 3으로 최소 1개 | 높이 1로 최소 1개 |
| 3 | 높이 4로 최소 1개 | 높이 2로 최소 1개 |
| 4 | 해당 없음 | 높이 3으로 최소 1개 |

실제 다리로 같은 높이의 연결 묶음을 다시 찾고, 각 묶음의 위·아래 출입 다리를 각각 집계합니다. 한 묶음 내부의 어느 타일에서 출발해도 되며, 모든 개별 타일에 위·아래 다리를 요구하지 않습니다. 높이 2·3은 양쪽 모두 필요합니다. 타일당 다리는 기존과 같이 최대 4개입니다.

전역 경계 다리 수의 최솟값은 유지했습니다. 다만 묶음별 출입 조건도 만족해야 하므로 실제 다리 수는 묶음 개수에 따라 더 많아질 수 있습니다. 예를 들어 높이 2 묶음이 3개면 높이 2↔3 다리는 최소 3개가 필요합니다.

## 기존 규칙 적용

- 높이 1은 전체 타일에 인접면 최소 2개, 다리 2~4개.
- 높이 1 연결 묶음은 4~8개, 높이 2는 4~6개. 실제 다리에서 묶음을 재계산.
- 같은 높이 다리 최소 하나, 인접 슬롯에만 중복 없는 다리, 높이 차이 0~1.
- 높이 경계 다리 수 3~7개 / 2~5개 / 2~3개와 보스→비보스 연결.
- 시작점의 외곽 배치·직접 연결 대상·시작점 간 거리·특수 지형까지 최소 3개 다리.
- 추가 타일까지 모두 포함한 전체 연결과 번호별 고정 높이·종류.
- 높이 4는 중앙, 높이 1은 외곽을 우선하며 불규칙한 고리를 구성. 인접 높이는 일부 같은 반지름에 섞일 수 있고 높이별 평균 반지름은 1>2>3>4 순서.

## 확인 결과

추가 타일의 유무 조합 1,024개를 모두 배치하고 독립 검증했습니다. 수량 72가지 전부 지원합니다. 묶음별 위·아래 출입 조건도 모두 검사했습니다. 전체 연결은 유지하지만 이 조건을 위반하는 이전 지도를 의도적으로 입력해 거부하는 회귀 검사도 포함했습니다. 실제 게임 시드 1,000개도 생성·검증했고 Python과 브라우저의 같은 시드 결과가 일치합니다. 시작점이 없는 묶음과 금지된 역방향 이동 간선을 넣은 데이터가 거부되는 것도 확인했습니다.

시드 10만 개를 추첨한 번호별 관측률은 test_results.json에 있습니다. 지정 확률과의 차이는 모두 1%포인트 미만입니다. 이는 확률 설정의 보조 점검이며 매 게임 일정 수량을 강제로 맞춘다는 뜻이 아닙니다.

실제 브라우저에서는 55·60·50개 샘플의 모든 물리적 다리 통로와 비연결 인접면 차단, 2→3 허용·3→2 차단, 다른 다리 양방향 이동, 입력과 390px 화면을 확인했습니다. 필드·전체 지도·미니맵·충돌은 같은 최종 맵 데이터를 사용합니다.
